# GUI source files

All interfaces use the KSJ dark-green rainforest palette and are generated by LocalScripts.

## Files

- `SurvivalHUD.client.lua` — health, hunger, thirst, stamina, night, biome and compact resource strip.
- `ClassSelection.client.lua` — seven class cards, stats and server purchase/equip request.
- `LobbyMenu.client.lua` — Normal, PvP and Team vs Team mode selection.
- `LobbyStations.client.lua` — panels for the physical Shop, Rewards, Trading and Redeem Code stations.
- `CampfireHealth.client.lua` — BillboardGui above the in-world campfire, not a large HUD panel.

## Install location

Create `StarterPlayer/StarterPlayerScripts/GUI` and add each file as a **LocalScript**. The Shared GameConfig ModuleScript belongs at `ReplicatedStorage/Shared/GameConfig`.

## Opening panels

Physical lobby ProximityPrompts or a server-controlled lobby interaction can fire these client BindableEvents:
- `ReplicatedStorage.OpenLobbyMenu`
- `ReplicatedStorage.OpenClassSelection`
- `ReplicatedStorage.OpenShopStation`
- `ReplicatedStorage.OpenRewardsStation`
- `ReplicatedStorage.OpenTradingStation`
- `ReplicatedStorage.OpenRedeemStation`

These BindableEvents are local to each client. A server ProximityPrompt handler should use a RemoteEvent to tell the specific client to open a panel, or the client can listen to ProximityPrompt.Triggered locally when appropriate. Do not try to fire a BindableEvent from the server.

## Required server integration

- `ReplicatedStorage/Remotes/EquipClass` RemoteEvent for class selection.
- `ReplicatedStorage/Remotes/SelectMode` RemoteEvent for lobby matchmaking (not implemented in the existing server baseline yet).
- `ReplicatedStorage/Remotes/RedeemCode` RemoteEvent for promo codes.
- Player Attributes: `CurrentNight`, `CurrentBiome`, `Hunger`, `HungerMax`, `Thirst`, `ThirstMax`, `Stamina`, `StaminaMax`.
- leaderstats values: `Diamonds`, `Coins`, `Wood`, `Scrap`, `Metal`, `ForestGems`.
- Campfire instance: Workspace child named `Campfire` with `CampfireHP` and `CampfireMaxHP` attributes.

## Important

These GUI scripts create the visual interfaces, but the shop catalog, reward granting, player trading, matchmaking, and secure server responses still need their server systems. No client-side GUI should grant currency, items, rewards, or classes by itself. Test on a separate experience before enabling these systems in the live game.
